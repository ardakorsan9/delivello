## Actionable for NOS (ranked)

1. **Ejection-pool insertion for unserved window orders (GES-style), with penalty counters** [#6, #5, #4].
   For each missing window order r: try the best feasible insertion on compatible trucks (type, capacity), allowing up to 60 min lateness. If none exists, choose a truck and eject a set E of 1–2 requests (prefer no-window and low-value ones) such that r becomes insertable, minimizing Σ p[e] (p is a penalty counter that grows every time a request fails to insert). Then reinsert E with regret insertion, and put back in the pool whatever still fails. Run this as a separate phase between ALNS rounds, and give it more time while it keeps raising the served-window count, as in #5's adaptive time budget. Accept moves with the SISR absences criterion [#4]: the summed absence counts of unserved window orders must not increase.
2. **Use lateness as a soft time window everywhere, including the bound** [#1, #8].
   #1 reports soft TWs raising profit by 179.54% on average over hard TWs. When pairwise windows conflict, treat each window as [a, b+60] with a linear value loss in (b, b+60], both in insertion scoring and in the CP-SAT pairwise-conflict bound. Some pairs that are "conflicting" under hard windows may become compatible, and serving such an order late often beats losing it.
3. **Route-pool set-partitioning polish** [#2].
   Log every distinct feasible route found during ALNS/GES, keyed by truck, since start cities and truck types differ. At the end (and maybe every N iterations), solve a CP-SAT model: at most one route per truck, each order at most once, maximize Σ value − λ_cost·cost − λ_co2·co2 − μ·empty_km. That is a linear stand-in for the min(1, ref/x) terms; set λ from the current solution's marginal score. This recombines window orders across trucks in a way single-route moves cannot.
4. **SISR string removal + blink insertion as an extra ALNS operator** [#4].
   Remove adjacent strings of stops on several trucks near the pickup/delivery cities of a missing window order, then do greedy insertion with blinks (β≈0.01). This frees time slack exactly where the conflicting windows are. It is cheap to add next to Shaw/worst/random removal and fits the existing adaptive weights.
5. **Incremental route re-evaluation with cached forward driver-state labels** [#7].
   At each stop, store arrival time, driving since the last break, and driving since the last rest. Re-simulate only from the insertion point, and stop as soon as the state matches the cached one again (schedule unchanged downstream) or a window is broken by more than 60 min. More evaluations per second means more GES/ALNS iterations in 24 h. Full backward labels as in #7 are more work. Optional.
6. **Multi-weight / small-population search over the score components** [#3, #8, #9].
   Run several seeds with different weights (fulfillment-heavy vs efficiency-heavy), keep a small Pareto archive, and recombine with an SREX-like crossover: take a subset of truck routes from parent A, fill from parent B, repair with regret insertion [#9]. Lower priority. Do it only if 1–3 are already in place.
